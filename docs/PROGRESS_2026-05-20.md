### 2. 战犯榜 PNG (commit `0d87651` / `32cf574` 中的 fix)

新增 `report/bin/render_criminals.py` —— 败方战犯检测 + 卡片 PNG。
按船种阈值表 + 事件级时间轴 + 消耗品使用情况综合判定。

判定逻辑分多条规则,踩中条件 ≥2 就上榜,raw_exp <500 自动头号战犯:

- **早死**: BB/CA/CL/CV <6min, DD/SS <8min
- **低输出**: BB<60k / CV<60k / CA<50k / CL<40k / DD<25k / SS<20k
- **抗线船潜在低**: BB<1.0M / CA<800k / CL<600k
- **侦查船侦查低**: CA<15k / CL<25k / DD<20k / SS<30k / CV<15k
- **裸经验**: <700 上榜 +1, <500 头号 +2
- **集火走位错** (事件级): 死前 60s HP 还 ≥80% max_hp,且当时队友还 ≥3 人活着
  (避免末期 1v 多被秒的无解情况误判)
- **装甲区暴毙** (事件级): 任意单次受伤 ≥30% max_hp
- **消耗品没用**: 强相关消耗品带了但 0 次使用 +1/条;全场总使用 ≤1 次 +1

要让事件级规则工作,Rust 端必须先暴露每笔伤害事件 + 每次消耗品激活,
所以做了几次 replayshark 扩展(见下面 Rust 部分)。

战犯卡用 PIL 渲染成 PNG,按 score 降序前 4 名展示。
战犯卡接入 `wows_full_report`:**战报 → 战犯 → 复盘** 三段竖向拼图(用户后期确认的顺序)。

### 4. Rust replayshark 扩展四件

加在 `tools/replayshark_battle_report.patch`(完整 patch 现在 700 行)。

#### 4.1 `damage_events` 时间轴

`BattleController` 内部有 `damage_dealt: HashMap<EntityId, Vec<DamageEvent>>` —
每笔伤害事件含 (attacker, victim, clock, amount)。原 battle-report 子命令
不输出这个,只输出聚合伤害。**战犯检测的"装甲区暴毙"和"集火走位错"两条事件级规则**
都需要这个,所以加了输出。

JSON 新增顶层 `damage_events: [{time_secs, attacker_entity_id, victim_entity_id, amount}]`。
time_secs 是 elapsed-from-battle-start(跟 DeathInfo.time_lived 同口径)。

#### 4.2 `consumable_uses` 时间轴

跟 damage 同理,packet handler 里看到 `Consumable` packet 就累计一条:

```rust
ConsumableUseOut {
    user_entity_id: u32,
    consumable_name: String,  // Recognized<Consumable> 的 Debug 名,或 Unknown 原串
    time_secs: f32,
}
```

JSON 新增 `consumable_uses: [{user_entity_id, consumable_name, time_secs}]`。

#### 4.3 `ship.consumable_slots` 嵌套

为了识别"带了 X 没开 X",必须知道每条船带了什么消耗品。
`Vehicle.abilities()` 是 `Option<Vec<Vec<(String, String)>>>`,外层=slot,
内层=该 slot 的可选 ability_name 列表(玩家二选一)。原 main.rs 取了第一项
导致漏选项 → 改成嵌套 dump,Python 端按 slot 整体判断"slot 内任一 variant
用过就算用过",避免把"侦察机/战斗机二选一 slot"误判成"两种都没开"。

JSON 字段 `ship.consumable_slots: [[ability1, ability2], [ability3], ...]`。

#### 4.4 ⭐ CV 飞机级消耗品(plane_refs 链路)— 今天最深的一段

**问题**:CV 玩家有"巡逻战斗机""引擎冷却"等飞机级消耗品(用户从 iwarship.net
截图给我证实),但 `ship.consumable_slots` 只能拿到舰体级的(自动损管 +
PCY038_FighterAuto),拿不到飞机级。

**调查链路**:

1. CV 玩家用过的 consumable enum 只有 `CatapultFighter` + `DamageControl` —
   飞机级消耗品没走标准 `Consumable` packet(或者三场样本里恰好没玩家用)。
2. wowsunpack `Aircraft` 结构只有 `category` + `ammo_type` 两字段,
   没 abilities。
3. 加 debug print 看 Aircraft pickle 的 top-level keys,找到 **`PlaneAbilities`**
   key(跟 ship 的 `ShipAbilities` 同构)。
4. 给 `Aircraft` 加 `abilities` 字段 + 在 build_aircraft 里 parse PlaneAbilities。
5. 但 plane 跟 ship 怎么关联?加 debug print 看 CV ship pickle,发现
   `A_TorpedoBomber.planes` / `A_DiveBomber.planes` / `A_SkipBomber.planes` 等组件,
   值是 `["PJAB211_SHINANO", ...]` (plane name 列表)。
6. 给 `Vehicle` 加 `plane_refs: Vec<String>` 字段,build_ship 时从这些 A_xxx
   组件里抽 planes 列表(去重)。
7. main.rs 在序列化 CV ship 时,对每个 plane_ref 调
   `GameParamProvider::game_param_by_name(plane_ref)`(**注意是 by_name 不是 by_index**,
   plane_refs 是 param name),拿到 plane param 后取它的 abilities 一起塞到 ship.consumable_slots。

结果:信浓现在 6 个 slot 都能看到:
- PCY037_CrashCrewAuto (自动损管)
- PCY038_FighterAuto (战斗机/舰体)
- **PCY034_ForsageBooster (引擎冷却 - 飞机级)**
- **PCY078_PlaneTacticalFighters (巡逻战斗机 - 飞机级)**
- **PCY081_ActiveManeuvering (主动机动 - 飞机级)**
- **PCY049_PlaneSmokeGenerator (飞机烟雾 - 飞机级)**

## 已知坑(下次要踩注意)

1. **Ability.categories() 永远空** — wowsunpack 在新 WoWs GameParams 里 parse 失败,
   只能拿 ability_name 字符串。所以 Python 端按关键字 substring 识别。
   想升级到精确的 enum 识别需要修 wowsunpack 的 Ability parser。

2. **CV 玩家三场样本里都没触发飞机级 packet** — `consumable_uses` log 里
   信浓/大凤等 CV 玩家只看到 `CatapultFighter` + `DamageControl`,没看到
   ForsageBooster / PlaneTacticalFighters。可能他们就是没用,也可能这些消耗品
   走的不是标准 Consumable RPC。下次跑实战时如果碰到 CV 玩家明显用了"引擎冷却"
   但 consumable_uses 里没记录,就要去挖 wows-replays decoder 里别的 packet 类型。

3. **`game_param_by_index` vs `game_param_by_name`** — `plane_refs` 里存的字符串
   是 plane 的 **name**(如 `PJAB211_SHINANO`),不是 index。必须用
   `GameParamProvider::game_param_by_name()` 才查得到。曾经踩过坑空跑半天。

4. **DD/CL 二选一 slot 处理** — Wisconsin 的 `[Spotter, Fighter]` slot 是
   玩家二选一。Rust 端按 slot 嵌套 dump,Python 端 `strong_consumable_slots()`
   按 slot 整体计数。"slot 内任一 variant 被用过就算用过"。

5. **战犯卡 + 战报 + 复盘拼图顺序定为**:战报 → 战犯 → 复盘。
   `wows_full_report` 里写死的。

6. **memory 已更新**:`deploy_layout.md` 和 `project_wows_qq_bot.md` 反映
   新 wows-bot 仓库结构(plugin/ + minimap/ + report/...)。
